# 멀티플랫폼 콘텐츠 분석 플랫폼 확장 기획 (초안, 미실행)

**상태: 기획 문서만 존재. 코드/DB/배포 어떤 것도 아직 변경하지 않음.**

## 배경

N인플은 현재 "네이버 키워드/순위/인플루언서 분석" 서비스다. 여기에 더해 사용자가 만든
콘텐츠(블로그 글·인스타 릴스/피드·유튜브 영상) 자체를 분석하고, 다음 콘텐츠 방향까지
제안하는 "콘텐츠 분석 플랫폼"으로 확장하자는 방향이 2026-08-08에 논의됨.

기존에 이미 구축된 콘텐츠 기획 워크플로우(키워드추천→글감찾기→제목생성→본문생성→발행후성과분석,
[src/app/dashboard/writing/](../src/app/dashboard/writing/))와 자연스럽게 이어지는 확장이며,
"콘텐츠 자산 프로필"(대분류/전문성 점수, `content_categories` 테이블 — migration-128 예정)과도
연결점이 있다.

## 목표 구조 (장기 비전)

```
N인플
├── 블로그 분석 (기존)
├── 인플루언서 분석 (기존)
├── 키워드 분석 (기존)
├── 콘텐츠 분석 (신규)
│    ├── 네이버 블로그
│    ├── Instagram (릴스 / 피드)
│    └── YouTube (롱폼 / Shorts)
├── 콘텐츠 디자인 (신규)
│    ├── 컬러 팔레트 자동 추출
│    ├── 썸네일 분석
│    └── 콘텐츠 스타일
└── AI 콘텐츠 전략 (신규)
     ├── 콘텐츠 재활용 (플랫폼 간 변환 제안)
     ├── 콘텐츠 아이디어
     ├── 플랫폼별 변환
     └── 경쟁 콘텐츠 분석
```

## 왜 전체를 한 번에 만들지 않는가

이건 새 기능 하나가 아니라 **데이터 소스가 3개 플랫폼으로 늘어나는 구조 변경**이고,
플랫폼마다 "공식적으로 가져올 수 있는 데이터의 범위"가 완전히 다르다. 확인 없이 설계부터
시작하면 나중에 API 제약 때문에 UI에 그려둔 지표를 못 채우는 상황이 생긴다. 그래서 먼저
플랫폼별 데이터 접근 가능성을 검증하고, 가장 리스크가 낮은 것부터 단계적으로 붙이는 게 맞다.

## 플랫폼별 데이터 접근 가능성 (검증 필요, 아래는 현재 알려진 공식 제약)

| 플랫폼 | 공개 지표(조회수/좋아요/댓글 등) | 자막/대본 | 이탈구간·시청 유지율 | 비고 |
|---|---|---|---|---|
| 유튜브 롱폼/쇼츠 | ✅ YouTube Data API v3 (공식, 무료 쿼터) | ✅ 자막 있는 영상은 API로 획득 가능 | ❌ 임의 영상 불가 — Analytics API는 **채널 소유자 본인**만 OAuth로 접근 가능 | 가장 접근성 높음, MVP 후보 1순위 |
| 네이버 블로그 | ✅ 이미 크롤링 인프라 있음(공개 HTML) | 해당 없음(텍스트 자체가 본문) | 해당 없음 | 기존 인프라 재사용 가능 |
| 인스타그램 릴스/피드 | ⚠️ Meta Graph API는 **본인 소유의 연동된 비즈니스/크리에이터 계정**만 인사이트 제공. 타인 게시물 공개 스크래핑은 ToS 위반 + 강한 안티봇 | ❌ | ❌ | **임의 URL 분석은 사실상 불가.** "내 계정 연동"으로 스코프를 좁혀야 함 |

**결론**: "URL 하나 넣으면 아무 콘텐츠나 분석"이라는 원래 비전은 유튜브에서만 거의 그대로
가능하고, 인스타그램은 사용자 본인이 계정을 OAuth로 연동했을 때만 가능하다. 이 제약을
MVP 범위 산정에 반영해야 한다.

## 단계별 로드맵 (제안)

### Phase 1 — 유튜브 롱폼 단건 분석 (MVP)
- 입력: 유튜브 영상 URL
- 공식 API로 확보: 제목/설명/썸네일/길이/조회수/좋아요/댓글수/업로드일
- 자막이 있는 영상은 자막 텍스트를 Claude에 넘겨 챕터 자동 분해(후킹→문제제시→핵심내용→
  사례→해결→정리→CTA), 톤앤매너, 반복 주제 추출
- **이탈 가능 구간 예측은 시청 유지율 데이터 없이 텍스트 구조만으로 하는 "AI 추정"이라고
  UI에 명확히 표시** (실측 데이터 아님)
- 컬러 팔레트: 썸네일 이미지에서 5색 추출 (기존 `chart-colors.ts`와 별개 유틸, node-vibrant류
  라이브러리 검토)
- 비용 구조: 영상 1건 분석 = Claude 호출 1~2회 → 기존 `LockOverlay`(포인트 차감) 패턴 재사용해
  AI 비용 통제

### Phase 2 — 콘텐츠 DNA 카드 + 저장/이력
- Phase 1 분석 결과를 카드 형태로 요약(주제/유형/톤/핵심 컬러/후킹·정보성·가독성·CTA 점수)
- 사용자별 분석 이력 저장 (아래 DB 스키마 초안 참고)
- "이 스타일로 내 콘텐츠 만들기" → 기존 제목생성/본문생성 워크플로우로 연결

### Phase 3 — 네이버 블로그 콘텐츠 분석 통합
- 이미 크롤링 중인 블로그 글에 동일한 "콘텐츠 DNA" 분석 적용 (신규 크롤링 불필요, 기존
  `blog_post_contents` 재사용 — `content_category_profile` 작업과 겹치는 부분 있으니 통합 검토)

### Phase 4 — 인스타그램 (본인 계정 연동 한정)
- Meta Graph API OAuth로 본인 비즈니스/크리에이터 계정 연동
- 본인이 올린 릴스/피드만 분석 가능 (경쟁 계정 분석은 스코프 밖으로 명시)

### Phase 5 — 플랫폼 간 비교 + 콘텐츠 재활용 제안
- 2개 이상 플랫폼 데이터가 쌓인 사용자 대상, 채널별 종합 점수/강점 유형 비교
- 유튜브 영상 1개 → 블로그/인스타 파생 콘텐츠 제안, 블로그 글 1개 → 릴스 후킹 문구+대본 제안
- 이 단계부터 진짜 "통합 콘텐츠 엔티티"가 필요함 (아래 참고)

## 데이터 모델 초안

기존에 발견된 문제: 순위확인(`keyword_rank_lookups`)·AI브리핑(`ai_briefing_exposures`)·
구글색인(`indexed_urls`)이 전부 `(user_id, blog_id, post_id)`를 키로 쓰지만 서로 모르는 별도
테이블이고, 통합 "포스팅" 엔티티가 없음 ([[naver_influencer_body_generator]] 참고). 이번 확장은
이 문제를 더 키우지 않으려면 **처음부터 플랫폼 공통 콘텐츠 엔티티**로 설계해야 한다.

```sql
-- 플랫폼 공통 콘텐츠 원장 (신규)
content_items (
  id, user_id, platform enum('naver_blog','youtube','instagram_reel','instagram_feed'),
  external_url, external_id, title, thumbnail_url,
  published_at, fetched_at, raw_metrics jsonb  -- 조회수/좋아요/댓글 등 플랫폼별 원자료
)

-- AI 분석 결과 (신규, content_items 1:1 또는 1:N 버전 관리)
content_ai_analysis (
  id, content_item_id, analyzed_at,
  topic, content_type, tone, color_palette jsonb,
  hook_score, info_score, readability_score, cta_score,
  chapters jsonb,  -- 유튜브 챕터 분해 결과
  raw_analysis jsonb  -- 원본 AI 응답 보관 (재분석 없이 재표시 가능하게)
)
```

기존 `keyword_rank_lookups`/`ai_briefing_exposures`/`indexed_urls`를 `content_items.id`로
조인 가능하게 만들지는 별도 마이그레이션 계획 필요 (RLS 전환 계획과 마찬가지로 손대는 범위가
크므로 이 문서에서 확정하지 않음).

## 플랜/가격 연계 (제안, 미확정)

- 유튜브/블로그 단건 분석: 포인트 차감(기존 `LockOverlay` 패턴) — AI 호출 비용이 건당 발생하므로
  구독 플랜에 무제한 포함시키지 않는 편이 안전
- 콘텐츠 DNA 카드 이력 저장·플랫폼 비교 대시보드: 인플루언서(₩44,000)/대행사(₩99,000) 플랜 부가 기능
- 최종 가격 정책은 Phase 1 실사용 데이터(평균 AI 비용/건)를 본 뒤 확정

## 리스크 요약

1. **인스타그램 임의 URL 분석은 사실상 불가능** — 이 문서 상단 표 참고. 비전 문서의 "인스타 릴스
   URL 하나 넣으면 분석"은 본인 계정 연동 시나리오로 축소해야 함
2. **유튜브 이탈구간/시청유지율은 추정치일 뿐 실측 아님** — UI에서 반드시 구분 표시 필요
3. **AI 분석 비용** — 영상 자막+챕터 분석은 블로그 텍스트 분석보다 토큰이 커서 건당 비용이 높을 수
   있음, Phase 1에서 실측 필요
4. **통합 콘텐츠 엔티티 도입은 기존 3개 테이블과의 관계를 새로 설계**해야 하는 구조 변경 —
   RLS 전환 계획([docs/rls-migration-plan.md](rls-migration-plan.md))과 마찬가지로 한 번에
   밀어붙이지 말고 파일럿 후 확산
